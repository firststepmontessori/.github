# Contributing

Thank you for helping First Step Montessori maintain a trustworthy and
accessible public presence.

## Workflow

1. Start all work from the `dev` branch.
2. Keep each commit focused and use a descriptive commit message.
3. Run the repository's documented validation commands.
4. Push the change to `dev` or a short-lived branch based on `dev`.
5. Merge into `main` only through a pull request.

Direct pushes, force pushes and deletion of `main` are prohibited.

## Content rules

- Do not add child names, photographs, videos or consent records.
- Do not add parent details, private contact lists, credentials or secrets.
- Do not publish unverified claims about accreditation, staff history, fees,
  schedules or programmes.
- Prefer plain language and accessible, semantic interfaces.
- Record material product or architecture decisions in project documentation.

## Reporting corrections

Use the content-correction issue form for factual or wording corrections. Avoid
including personal or sensitive information in public issues.
